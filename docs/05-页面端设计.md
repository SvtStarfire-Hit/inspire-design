# 05 · 页面端设计

> InspireDesign 的页面端：人独立使用时的方法论浏览器与引导页。
> 与 MCP 端消费**同一份数据**（见 03-数据契约.md），只是呈现方式不同。

---

## 1. 定位

| | MCP 端 | 页面端 |
|---|---|---|
| 消费方 | AI agent | 人 |
| 形态 | 工具调用返回"指令版"约束 | 页面浏览"教程版"内容 |
| 场景 | 已接入 MCP 的 AI IDE 会话中 | 人想先弄明白整套流程；或未接入 MCP 时独立使用 |

**页面端的独特价值**：

- 在你还没有接入 MCP、或想脱离 AI 独立回顾流程时，仍然可以按方法论推进
- 提示词模板集中可查可复制——适合"我知道该说什么，但想看看范例"
- 环境要求、坑清单、回退影响面等人读友好的信息在这里完整展示

---

## 2. 信息架构

```
InspireDesign 页面端
├─ 首页                定位说明 + 模式选择（WPF / 稍后开放的灰色项）
├─ 流程全景            9 阶段卡片总览（Mermaid 流程图 + 阶段卡片）
├─ 阶段详情 ×9         每个阶段的完整内容（见 §3）
├─ 工具链              测量/出图脚本说明 + 环境要求清单
└─ 关于                核心理念（01 文档的精简版）
```

导航：顶部主导航（首页/流程全景/工具链/关于）+ 流程全景中的阶段卡片进入详情。阶段详情间支持"上一阶段 / 下一阶段 / 回到全景"。

---

## 3. 阶段详情的区块结构（映射约束包字段）

| 页面区块 | 对应数据字段 | 呈现方式 |
|---|---|---|
| 目标 | `goal` | 头部一句话 |
| 产物 | `deliverables` | 文件卡片（名称 + 路径 + 说明） |
| 出口条件 | `exitCriteria` | 检查清单样式 |
| 前置依赖 | `dependencies` | 提示条（"需要先完成：…"） |
| 规则 | `rules` | 要点列表 |
| 该怎么做 | `guidance` | 编号步骤 |
| 提示词模板 | `aiPromptTemplate` | 代码块 + **一键复制按钮** |
| 常见坑 | `pitfalls` | 警示样式列表 |
| 回退影响面 | `revisionImpact` | 折叠区块（"如果你要回头改…"） |
| 人确认点 | `humanCheckpoint` | 底部高亮提示（"做完后停下来确认：…"） |
| 环境要求 | `environment` | 仅在阶段 6 显示（表格 + 检查命令复制） |

数据结构完全复用 03 契约——页面端不产生第二套数据。

---

## 4. 交互要点

1. **一键复制**：提示词模板、检查命令、运行命令都提供复制按钮（这是页面端最高频的操作）
2. **阶段导航**：任意阶段可达；不做"未完成不许进入下一阶段"的门禁（与 MCP 端一致：门禁在人）
3. **环境清单可带走**：工具链页的环境要求支持"复制全部为清单文本"，方便粘给 AI 让 AI 去检查
4. **不追踪进度**：页面端同样不记录"做到了第几阶段"——进度由人掌握（与无状态原则一致）。如后续试用发现需要，再评估

---

## 5. 技术选择（自举）

**原则：用本方法论做自己。**

| 项 | 选择 | 理由 |
|---|---|---|
| 载体 | HTML + CSS 为主 | 与方法论要求一致（自举示范） |
| 图标 | 内联 SVG | 同方法论：现成图标集复制，不自己画 |
| 流程图 | Mermaid（CDN 引入） | 流程全景的 9 阶段流转用 Mermaid 画 |
| 脚本 | 少量原生 JS（导航/复制/折叠） | 原型阶段不引入框架 |
| 数据 | 与 MCP 端同一份 JS 数据模块 | 单一事实来源（03 契约） |

原型阶段约束：

- 不引入 Vue/React/构建工具——页面端本身应该是"可以被 AI 一次生成"的简单形态
- 页面端的产出过程本身就是方法的演示：先定令牌（页面自己的 tokens.css）→ 组件样式 → 页面 → 体检（自测）→ 出图

---

## 6. 与 MCP 端的数据共享方式（原型阶段）

```
数据模块（JS，ESM）
   ├─ MCP 服务：直接 import（Node 运行时）
   └─ 页面端：构建/生成时内联为页面数据（或页面用 <script type="module"> 直接加载）
```

原型阶段接受"页面端与脚本同目录、通过开发服务器或 file:// + 内联"的简单形态；
不引入打包流程。何时升级（如拆分为独立发布），由试用情况决定。

---

## 7. 待定项（试用后决定）

- 是否需要 Mermaid 渲染以外的可视化（阶段卡片的完成状态标记等）
- 是否需要"引导模式"（页面端逐步提问式引导，接近 MCP 端的体验）
- 多语言/多模式切换的展示形态（模式切换后提示词术语如何联动）

以上均属“先不做，用了再说”的范畴（原型阶段原则：先固化、边用边改、不过度设计）。

---

## 8. 实现状态（2026-09-11）

页面端已按本文档 §2-§6 落地于 `web/`：

| 项 | 落地方式 |
|---|---|
| 形态 | 单页 + hash 路由：首页 / 流程全景 / 阶段详情 ×9 / 工具链 / 关于；零框架、零构建 |
| 数据 | `<script type="module">` 直接加载 `data/*.js`（与 MCP 端同源；含 WPF 模式字段级覆盖的合并） |
| 交互 | 提示词模板 / 检查命令一键复制（含 file:// 降级）；环境清单可整单复制；阶段任意跳转、无门禁；不追踪进度 |
| 自举 | 先定令牌（`web/assets/tokens.css`）→ 组件（`app.css`）→ 页面（`index.html`） |
| 流程图 | Mermaid 本地 vendor 优先（`web/vendor/`），CDN 兜底，均失败降级为文字链 |
| 启动 | `npm run web`（`serve-web.js`，零依赖本地服务器，默认 4173 端口） |

§7 的三个待定项（完成状态标记 / 引导模式 / 多模式切换展示）维持未做——“用了再说”。
已完成的验证：全路由无头浏览器巡游（9 阶段 / 环境表 / 复制按钮 / Mermaid 渲染 / 未知阶段兜底）全部通过。
