# 06 · 设计工具链

> check-layout.js 与 export-png.py 的定位、环境声明与集成方式。
> 它们**不是 WPF 专属**——操作对象是 HTML 设计稿与浏览器，所有模式共享。

---

## 1. 定位

| | |
|---|---|
| 归属 | InspireDesign（权威副本）→ 复制到目标项目的 `design/` 目录使用 |
| 消费者 | 所有模式（WPF / Vue / React / 通用） |
| 对流程的作用 | 支撑阶段 6"体检出图"：把肉眼看不到的问题机器化检出 + 产出交付图 |
| 设计原则 | 零框架依赖；错误信息写给 AI 看（可执行）；输出尽量结构化 |

**在流程中的位置**：

```
阶段 5（规格页完成）
   ↓
阶段 6（体检出图）—— 需要环境 → AI 检查/确认/安装 → 运行两个脚本 → 通过标准
   ↓
阶段 7（写映射）—— 体检通过是前提
```

## 2. 脚本说明

### 2.1 check-layout.js — 设计稿体检

| 项 | 说明 |
|---|---|
| 用途 | 检出肉眼看不见的布局问题（1px 出框、长文案破版、容器溢出） |
| 用法 | `node check-layout.js <file.html> <宽> <高>` |
| 原理 | 无头浏览器打开页面 → CDP 注入检查脚本 → 输出 JSON 报告 |
| 输出 | `vOverflow`（纵向溢出）/ `hOverflow`（横向溢出）/ `textLeak`（文字出框） |
| 通过标准 | 三类均为 `[]` |
| 依赖 | Node 22.4+（全局 WebSocket）；Edge 或 Chrome |

已知边界（文档已声明）：

- 只查"形状"，不查"好不好看"
- 对 `position: absolute` 的装饰性元素可能误报
- **文案长度是假的**——所以流程要求先塞"故意很长"的样例文字再体检

### 2.2 export-png.py — 出图

| 项 | 说明 |
|---|---|
| 用途 | HTML 设计稿 → PNG 交付图 |
| 用法 | `python export-png.py`（全部） / `python export-png.py fig1`（单张） |
| 尺寸来源（优先级） | PAGES 表 → HTML 注释 `<!-- @render W H notrim -->` → 缺省 1600×3200 + 裁剪 |
| 依赖 | Python 3.9+；Pillow（可选，自动裁剪用）；Edge 或 Chrome |

两种图两套参数：

- **页面稿**（窗口壳层，fig1）：固定尺寸，不裁剪
- **规格稿**（文档式长页，fig2+）：高度给足，自动裁剪空白

## 3. 环境要求（声明式）

随阶段 6 的约束包透出（数据结构见 03-数据契约.md §5）：

| 组件 | 最低版本 | 可选 | 检查 | 安装 |
|---|---|---|---|---|
| Node.js | 22.4 | 否 | `node --version` | https://nodejs.org 或 `winget install OpenJS.NodeJS` |
| Python | 3.9 | 否 | `python --version` | https://python.org |
| Pillow | — | 是 | `python -c "import PIL"` | `pip install pillow` |
| Edge / Chrome | 现代 | 否 | 检查常见安装路径 | 系统通常自带 Edge |

**交互链路**（工具只声明，AI 执行）：

```
约束包返回 environment
  → AI 逐项运行 check 命令
  → 报告缺失项 + 影响 + 安装命令
  → 用户确认
  → AI 执行安装 → 复检
  → 继续流程
```

## 4. 集成方式

### 4.1 分发（复制到目标项目）

新项目启用工具链时（通常发生在阶段 6 首次需要时）：

```
InspireDesign/check-layout.js  →  <目标项目>/design/check-layout.js
InspireDesign/export-png.py    →  <目标项目>/design/export-png.py
```

AI 执行复制（或用户手动）；约束包的 `scripts[].usage` 给出运行方式。

### 4.2 执行（原型阶段：AI IDE 终端）

原型阶段由 AI 编码助手在其终端直接运行两个脚本——约束包里带 usage 与 pass 标准，AI 不需要猜命令。

### 4.3 后续增强（暂不实现）

`run_design_check` MCP 工具：直接执行 check-layout.js 并返回结构化结果。
判定依据：AI IDE 已有终端能力；此工具的增量价值主要是减少拼命令出错，留待试用后评估（与 04 文档 §5 一致）。

## 5. 错误信息原则（写给 AI 看）

脚本的报错信息读者是 AI（顺便人也能看懂），标准是"**可执行**"：

| 要素 | 示例 |
|---|---|
| 缺什么 | "缺少 Pillow" |
| 影响什么 | "裁剪已跳过（截图已正常生成）" |
| 怎么装 | "如需裁剪请运行：pip install pillow" |
| 装完怎么办 | "装完后重跑本脚本" |

**禁止**：抛裸堆栈（对 AI 是干扰信息）。
